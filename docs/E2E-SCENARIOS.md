# E2E 테스트 시나리오 카탈로그

버디버드 앱의 Maestro e2e 테스트가 **무엇을 지키는지**를 사람이 읽을 수 있는 절차로 정리한 문서입니다.
실행 방법·testID 규약·검증 한계 등 규칙은 `docs/CONVENTIONS.md` §8이 단일 출처이며, 이 문서는 시나리오 내용만 다룹니다.

| # | 시나리오 | 한 줄 요약 | 태그 |
|---|---|---|---|
| 01 | 온보딩 완주 | 처음 설치한 사용자가 프로필을 만들고 학습 화면에 도달한다 | smoke |
| 02 | 탭 이동과 데이터 표시 | 만든 데이터가 앱 전체에서 일관되게 보인다 | smoke |
| 03 | 학습 세션 시작 + 중도 종료 | 단어를 골라 세션을 시작하고 안전하게 빠져나온다 | smoke |
| 04 | 프로필 편집 | 저장된 프로필을 수정할 수 있다 | smoke |
| 05 | 단어 생성 | 사용자가 직접 단어를 녹음해 추가할 수 있다 | smoke |
| 06 | 녹음 다듬기 | 녹음을 들어보고 다시 녹음한 뒤 저장할 수 있다 | regression |

- **smoke**: 핵심 happy path. 로컬 검증·(추후) CI 기본 실행 대상 (`yarn e2e:android:smoke`)
- **regression**: 회귀 감시용 심화 플로우. nightly/수동 실행 (`yarn e2e:android` 전체에 포함)

파일 위치: `.maestro/flows/<번호>-<이름>.yaml`, 공통 절차는 `.maestro/subflows/complete-onboarding.yaml`

---

## 공통 절차 — 신규 사용자 온보딩 완주 (subflow)

모든 시나리오는 "방금 설치한 사용자"에서 시작합니다. 02~06은 이 절차를 재사용합니다.

1. 앱을 초기화 상태로 실행한다 (저장 데이터 전체 삭제, 마이크·알림 권한은 미리 허용)
2. (debug 빌드 전용) 개발 환경 방해 요소를 자동 정리한다 — dev-client 런처에서 Metro 서버 연결, dev menu 인트로 닫기, 앱 업데이트 모달 닫기, 에뮬레이터 ANR 다이얼로그 처리
3. 온보딩 웰컴 화면이 보이는지 확인한다
4. "시작하기" 버튼을 누른다
5. 프로필 입력 화면이 보이는지 확인한다
6. 이름 "Mango"를 입력하고 키보드를 내린다
7. 종 목록에서 "사랑앵무" 칩을 선택한다 (종은 필수 항목)
8. "시작하기"(제출) 버튼을 누른다
9. 홈 도달 후 오디오 수집 동의 팝업(BB-245)이 뜨면 "거부"를 눌러 닫는다 — 초기화 상태에선 항상 표출

> 생년월일은 기본값이 있어 건드리지 않습니다. 이름을 영문으로 입력하는 이유와 debug 전용 단계의 상세는 CONVENTIONS §8.3 참고.
> 동의 팝업은 "거부"로 닫습니다 — 테스트 중 실제 녹음(05·06)이 수집 대상이 되지 않도록. 거부해도 앱 동작에는 차이가 없습니다.

## 01 — 온보딩 완주 [smoke]

**지키는 것**: 앱의 유일한 진입 관문. 신규 사용자가 프로필을 만들면 반드시 학습 화면에 도달해야 한다.

1. (공통 절차로 온보딩을 마친다)
2. 홈(학습) 화면에 도달했는지 확인한다 — 화면을 아래로 스크롤해 "학습 시작" 버튼 표시 확인

**잡아내는 회귀**: 앱 부팅 실패, 온보딩 라우팅·폼 제출·프로필 저장·내비게이션 게이트 전환(온보딩→탭)의 고장.

## 02 — 탭 이동과 데이터 표시 [smoke]

**지키는 것**: 온보딩에서 만든 데이터가 각 탭에서 일관되게 보인다.

1. (온보딩을 마친다)
2. 단어 탭으로 이동한다 → 단어 화면 도착 확인(단어 추가 버튼 표시)
3. 기본 제공 단어 "안녕"이 보이는지 확인한다 — 프리셋 시딩 검증
4. 프로필 탭으로 이동한다 → 프로필 화면 도착 확인(프로필 편집 버튼 표시)
5. 온보딩에서 입력한 이름 "Mango"가 보이는지 확인한다 — 저장 데이터 일관성 검증
6. 홈 탭으로 돌아와 "학습 시작" 버튼을 확인한다

**잡아내는 회귀**: 탭 내비게이션 고장, 단어 라이브러리 시딩 누락, 프로필 데이터 표시 오류.

> 각 탭 이동 직후 그 화면에만 있는 요소를 먼저 확인합니다 — "안녕"은 홈 화면에도 보이기 때문에, 이것만 확인하면 탭 이동이 실패해도 테스트가 통과해버리는 함정이 있습니다.

## 03 — 학습 세션 시작 + 중도 종료 [smoke]

**지키는 것**: 제품의 핵심 가치인 학습 세션이 시작되고, 사용자가 세션에 갇히지 않고 빠져나올 수 있다.

1. (온보딩을 마친다)
2. 홈에서 기본 제공 단어 "안녕"이 보이는지 확인한다 (기본으로 선택되어 있음)
3. 학습 시간은 기본 프리셋(중간·1시간)을 그대로 둔다
4. "학습 시작" 버튼이 **활성화**되어 있는지 확인한다 — 단어·시간 선택이 시작 조건을 채우는 로직 검증
5. "학습 시작"을 누른다
6. 세션 진행 화면이 보이는지 확인한다
7. **중도 종료 ①(뒤로가기)**: 뒤로가기를 누른다 → 종료 확인 다이얼로그 표시 확인
8. "종료"를 눌러 확정한다
9. 세션 화면이 사라지고 홈으로 복귀했는지 확인한다
10. 홈에서 "학습 시작" 버튼이 **활성화**되어 있는지 확인 후 다시 누른다 — 종료 후에도 단어·시간 선택이 유지되는지 검증
11. 세션 진행 화면이 보이는지 확인한다
12. **중도 종료 ②(종료 버튼)**: 화면의 "종료" 버튼을 누른다 — 설계상 확인 다이얼로그 없이 즉시 종료
13. 세션 화면이 사라지고 홈으로 복귀했는지 확인한다

**잡아내는 회귀**: 세션 시작 파이프라인(권한→설정 저장→화면 전환), 뒤로가기 가로채기·종료 확인 다이얼로그, 종료 버튼 즉시 종료, 종료 후 복귀 경로의 고장.

> 세션을 끝까지 기다리지 않습니다(중도 종료). 종료 경로 두 가지(뒤로가기 확인 다이얼로그·종료 버튼 즉시 종료)를 모두 검증합니다. 세션 자연 완주는 수 분간 오디오 재생에 의존해 e2e 범위 외입니다(§8.4).

## 04 — 프로필 편집 [smoke]

**지키는 것**: 저장된 프로필을 수정할 수 있다.

1. (온보딩을 마친다)
2. 프로필 탭으로 이동해 "Mango" 표시를 확인한다
3. "프로필 편집"으로 들어간다 → 이름 입력칸 표시 확인
4. 이름을 지우고 "Coco"로 입력한 뒤 키보드를 내린다
5. 화면을 스크롤해 저장 버튼을 찾아 누른다
6. 편집 화면이 닫히고 프로필 탭에 "Coco"가 보이는지 확인한다

**잡아내는 회귀**: 편집 화면 진입, 폼 수정·저장, 저장 후 표시 갱신의 고장.

> 아바타 변경(사진 권한 필요)·종 변경·생년월일 변경은 범위 외 — 이름 수정만 다룹니다.

## 05 — 단어 생성 [smoke]

**지키는 것**: 사용자가 직접 단어를 만들어 학습 콘텐츠를 늘릴 수 있다 (녹음 절차 + 저장).

1. (온보딩을 마친다)
2. 단어 탭으로 이동해 "안녕" 표시를 확인한다
3. 단어 추가 버튼을 눌러 생성 모달을 연다 → 이름 입력칸 표시 확인
4. 단어 이름 "Bori"를 입력하고 키보드를 내린다
5. 녹음 버튼을 눌러 녹음을 시작한다
6. 약 2초 후 녹음 버튼을 다시 눌러 정지한다
7. 미리듣기 행이 나타나는지 확인한다 — 녹음 완료 상태 진입 검증
8. 저장 버튼이 **활성화**되어 있는지 확인한다 — "녹음 완료 + 이름 입력" 조건 로직 검증
9. 저장을 누른다 → 모달이 닫히는지 확인
10. 단어 목록에 "Bori"가 보이는지 확인한다

**잡아내는 회귀**: 녹음 파이프라인(시작→정지→파일 생성), 저장 조건 로직, 단어 CRUD·목록 갱신의 고장.

> 에뮬레이터 녹음은 무음이어도 통과합니다 — 오디오 **내용**은 검증하지 않습니다(§8.4).

## 06 — 녹음 다듬기 [regression]

**지키는 것**: 녹음이 마음에 안 들 때 들어보고 다시 녹음하는, 녹음기 상태 머신의 왕복 경로.

1. (온보딩을 마친다)
2. 단어 탭 → 단어 추가 → 이름 "Kiwi" 입력
3. 1차 녹음을 하고 정지한다 → 미리듣기 행 표시 확인
4. 미리듣기(재생) 버튼을 누른다
5. **재녹음**: 녹음 버튼을 다시 누른다 (별도 재녹음 버튼 없음 — 녹음 완료 상태에서 녹음 버튼 재탭이 재녹음)
6. 미리듣기 행이 **사라지는지** 확인한다 — 이전 녹음이 폐기되고 상태 머신이 리셋됐다는 증거
7. 2차 녹음을 하고 정지한다 → 미리듣기 행 재등장 확인
8. 저장 활성화 확인 → 저장 → 목록에 "Kiwi" 표시 확인

**잡아내는 회귀**: 녹음기 상태 머신(녹음↔재생↔재녹음) 전환 오류 — 실제 수정 이력이 있는 영역의 회귀 감시.

> 재생 **소리**는 검증하지 않습니다 — 상태 전환(미리듣기 행의 소멸/재등장)까지만.

## 이 스위트가 검증하지 않는 것

`docs/CONVENTIONS.md` §8.4가 단일 출처입니다. 요약: 오디오 내용(무음도 통과)·세션 자연 완주·재생 소리·iOS 플로우는 README 수동 체크리스트 몫입니다.

## 시나리오를 추가·수정할 때

- 플로우는 "사용자 절차" 단위로, 모든 행동을 관찰 가능한 결과와 짝지어 작성합니다 (§8.1)
- 탭·화면 전환 직후에는 그 화면 고유 요소를 먼저 assert합니다 (02의 함정 참고)
- 온보딩이 필요한 시나리오는 공통 subflow를 재사용합니다
- 새 플로우 도입 시 smoke 태그는 2회 연속 green 확인 후에 부여합니다
