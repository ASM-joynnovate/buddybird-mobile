# API and durable upload services

The rewrite has two custom HTTP writes: `/api/v1/words` and `/api/v1/captures`. All reads are native Firebase operations. No REST read endpoint, bearer header, token registration endpoint, topic subscription, feedback read/update, or new server operation is introduced.

## Integration

Mount `QueryClientProvider` with `queryClient` and call `connectQueryLifecycle()` once. These services are independent of React components:

- `identityQueryOptions()` / `ensureAnonymousIdentity()` return the restored default native Firebase UID, or coalesce one anonymous sign-in. Identity query uses `networkMode: always` so the restored UID is available offline. Auth changes remain available through `subscribeIdentity()`.
- `updateQueryOptions()` / `fetchUpdatePolicy()` read Remote Config. Record the attempt before fetching. `shouldCheckUpdate()` controls cold-start and six-hour foreground attempts, including after failure. `evaluateUpdate()` compares marketing versions and forced/soft decisions. UI owns prompt order, deduplication and forced non-dismissability. `dismissUpdate()` persists the exact latest version; `openStore()` uses native URL then HTTPS fallback.
- `feedbackMutationOptions()` / `submitFeedback()` validate trimmed input, ensure shared auth and create a Firestore feedback document with `serverTimestamp()`. Automatic mutation retry is disabled. UI disables all form dismissal/editing during submission and retains text on failure. `countFeedbackDay()`, `feedbackThreshold()` and `consumeFeedbackPrompt()` operate inside `updateData()`.
- `initializeTelemetry()` reads OS ATT before enabling Analytics, Crashlytics or Clarity. Native Firebase configuration must start with Analytics and Crashlytics auto-collection disabled. `track()` enforces all declared event payloads in `api/events.ts`; `screen()` emits named screens. UI owns reachable event timing. `setSessionReplayPaused(true)` applies throughout the active-session screen, including new Clarity sessions. `createPerformanceReporter()` samples UI delay every 100 ms and accepts audio-delay samples; each kind emits strictly above 200 ms, at most once per five seconds and twenty times per session.
- Install `installGlobalErrorReporting()` once. It chains existing global exceptions and React Native rejection reporting, while adding Crashlytics context and `app_error`. Hermes rejection tracking is explicitly enabled in release builds as well.
- At the JS entry point register `registerBackgroundPushHandler()` and check `getIsHeadless()` before mounting normal bootstrap. Background receipts enter a separate MMKV inbox; it never creates fresh app data. After successful migration, `mergePushReceipts()` imports receipts with verified app-store writes before clearing inbox records. `startPush()` installs listeners and requests registration only after a profile exists. The app receipt list retains the newest twenty metadata-only receipts. Pending inbox entries remain until successful import, including when migration is blocked.
- After successful migration call `startUploads()` once and retain its cleanup function. It owns UID arrival, foreground, network-reconnection and cold-start triggers. Call `queueWordUpload(id)` on recorded-word creation, `triggerUploads("accumulation")` when captures accumulate, and `triggerUploads("session_end")` after durable session/recovery capture handoff. `setUploadConsent()` commits consent before triggering new requests. `drainFileDeletes()` is also available after explicit user file deletion.

## Upload ownership and file safety

The HTTP transport performs exactly one attempt. Fetch and response reading share a timeout (30 seconds for words, 60 seconds for captures); caller cancellation aborts the request. Optional JSON parsing permits arbitrary successful word responses and converts malformed capture responses into unresolved results. Upload calls have no TanStack retry layer.

The persistent worker has separate serialized word/capture streams. Multiple triggers coalesce; a condition-changing trigger during a failed request permits one later drain, while accumulation-only triggers do not bypass failure suppression. It rereads consent before each request, including each single-item retry; the native adapter checks again after ZIP assembly and immediately before `fetch`. Blank origin, missing UID, cancellation or denied/unknown consent prevent transmission. The configured origin must be HTTPS without URL credentials, query or fragment.

Words keep their original library ID and original audio file. Only recorded library entries are sent, oldest first. Any 2xx accepts; any 4xx reports and continues; 5xx/transport failures stop until another trigger. Missing/unreadable references remain local. Successful/rejected pending markers are cleared only after persistence; every cold start or grant re-adds all recorded words. There is no permanent success ledger. A response clears a pending word only if its current audio URI and update timestamp still match the sent revision; replacing a recording during upload keeps and subsequently sends the newer revision.

Captures use frozen migration/registration metadata and stable IDs. Batches contain at most ten readable files and at most 9 MiB of source bytes, except an oversized first file is submitted alone for a server decision. `fflate` streams DEFLATE level 2 ZIPs from 64 KiB file chunks, yielding between chunks. Exact ZIP entry names also appear in metadata. ZIP output is written incrementally into the app cache and removed after each outcome; abandoned temporary ZIPs are removed before a later batch. This retains the 1.1.0 deployment target without adding a native ZIP dependency that raises minimum iOS.

A 2xx response resolves only explicitly successful/rejected sent IDs. Partial responses continue while making progress. Unknown IDs/statuses and malformed bodies preserve unresolved data; no progress ends the drain. Multi-item 4xx requests split only the actual sent items into singles; a single-item 4xx resolves as rejection. 5xx, cancellation, unexpected statuses and local I/O errors retain pending captures. A confirmed absent file removes only its stale queue record: `exists: false` alone is insufficient, so the adapter requires a successful parent listing that omits the entry.

Queue removal and insertion into `pendingFileDeletes` occur in one verified store write. Only afterward may cleanup delete a source file. Cleanup rechecks live word media, historical session snapshots, active session drafts, profile photo and unresolved captures, including URI rebasing. File failure retains its durable cleanup entry. Archived word records do not alone retain media, but historical and active-session snapshots do. There is no unuploaded-capture eviction or migration-time deletion.

## Checks and remaining device acceptance

Run `yarn exec tsx --test test/api.test.ts test/policy.test.ts test/uploads.test.ts test/http.test.ts`. These exercise actual HTTP timeout/body behavior, ZIP entry bytes, coalesced identity, policy boundaries, partial outcomes, actual-sent single splitting, cancellation and consent gates, failure suppression, failed persistence, historical file protection and recollection on later cold starts.

Native ATT/Clarity/Firebase delivery, native file handles under real OS storage pressure, actual push delivery/headless launches, app-update UID continuity, store linking, and background execution must also be exercised on devices. Server idempotency, Firestore rules and the 180-day retention commitment still require server confirmation. No live upload, feedback submission, push send or store release is performed by these checks.

Current SDK implementation was checked against installed package types/source and official [React Native Firebase messaging](https://rnfirebase.io/messaging/usage), [Microsoft Clarity React Native SDK](https://learn.microsoft.com/en-us/clarity/mobile-sdk/react-native-sdk), and [fflate streaming documentation](https://github.com/101arrowz/fflate#usage). Product behavior comes only from the clean-room compatibility contracts in `api-deployment.md` and `data-native.md`.
