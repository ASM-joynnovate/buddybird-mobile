# I18N — 로케일·번역·로케일 콘텐츠 정책

앱의 언어 결정과 로케일별 콘텐츠(프리셋 단어·오디오) 규칙. 이관 이력·감사 기록은 `docs/I18N-COMPLETION.md`(BB-155) 참고.

## 1. 로케일 결정

- 지원 로케일은 `SUPPORTED_LOCALES = ['ko', 'en']` (`features/i18n/i18n-resources.ts`) — 새 로케일 추가는 별도 정책 결정 필요
- 앱 로케일 우선순위: **인앱 선택(stored locale) > 기기 언어** — 초기값은 기기 언어(`expo-localization` → `normalizeLocale`), 프로필 탭의 언어 전환 버튼(`components/profile/profile-language-toggle.tsx`)으로 변경하면 `@buddybird/locale`에 영속되어 재시작 후에도 유지된다 (2026-07-16 "인앱 언어 선택 UI 없음" 정책 폐지)
- 전환은 UI에 즉시 반영된다(전 화면 렌더 시점 `t()` 해석). **번역 문자열을 state에 고정 저장하지 않는다** — 에러 메시지 등은 키/플래그를 저장하고 렌더 시점에 해석 (선례: `training-context`/`word-library-context`의 `loadFailed`)
- **미지원 언어 기기는 `DEFAULT_LOCALE = 'en'`으로 fallback** — UI와 프리셋 단어가 함께 영어를 따른다 (2026-07-16 ko→en 전환, ko 기기는 기존대로 한국어)

## 2. 번역 리소스

- 모든 사용자 노출 문자열(화면 텍스트·Alert·접근성 라벨)은 `features/i18n/i18n-resources.ts` 경유 — 하드코딩 금지. `AppCopy` 타입에 키를 먼저 추가하면 ko/en 동시 작성이 컴파일 타임에 강제된다
- 접근성 전용 키는 `*A11y` 접미사, ko 카피는 해요체, en 카피는 typographic apostrophe(`’`) 사용
- features 레이어는 JSX/훅 금지이므로 `t`(또는 `locale`)를 마지막 인자로 주입받는다 — 선례: `profile-validation.ts`, `duration-format.ts`, `getSpeciesOptions(locale)`
- 로그 전용 메시지(`reportError`/`console.warn`에만 전달)와 `components/debug/*`는 번역 비대상

## 3. 로케일 콘텐츠 (프리셋 단어·오디오)

- 프리셋 단어는 UI 카피가 아니라 **앵무새 학습 콘텐츠** — **전 로케일 프리셋의 유니온**(ko 4개 안녕/사과/사랑해/다녀와 + en 2개 Hi/Hello)을 언어 설정과 무관하게 항상 시드하고, **표시 여부만 앱 로케일로 분기**한다 (BB-407): `SEED_PRESETS` 시드 + `filterEntriesByLocale`(둘 다 `features/word-library/word-library-model.ts`)를 `word-library-context` 의 `entries` 에 적용
  - 로케일 전환은 표시 분기만 — 재시드·삭제 없음. reconcile 을 로케일 무관으로 유지해야 entry id 가 안정적이다 (training 이 `wordId` 를 세션 간 참조)
  - 프리셋 로케일은 스키마 필드가 아니라 **키 접두로 파생** (`presetLocale`: `en-` 접두 → en, 무접두 → ko)
  - 시드는 hydrate 시 reconcile 로 정합화 — 기존 설치도 다음 hydrate 에 누락 프리셋(en 등)이 추가된다
- 프리셋 오디오는 `assets/audio/<locale-dir>/` 로케일 디렉토리로 관리 (`ko-kr/`, `en-us/`), 파일명은 `default_<단어>.m4a` 양식
- `preset://` 오디오 매핑 키(`PRESET_AUDIO_MODULES`, `features/audio/audio-source-resolver.ts`)는 단일 네임스페이스 — 비-ko 키는 로케일 접두 필수 (예: `en-hi`, `en-hello`), ko 키는 하위 호환을 위해 무접두 유지

## 4. 네이티브 문자열

- 세션 알림의 **제목·부제목**은 JS가 `t()`로 해석해 `sessionAudioEngine.start()`의 `notification` 필드로 넘긴다 — 인앱 언어 전환을 따른다 (`features/i18n/i18n-resources.ts` §`sessionNotification`). 회차 자리표시자 `%{cycle}`·`%{total}`은 네이티브가 갱신할 때마다 치환하므로 JS에서 미리 보간하지 않는다
- 그 밖의 Android 네이티브 문자열(알림 채널명·설명, 액션 라벨)은 `res/values/strings.xml`(ko) + `res/values-en/strings.xml`로 관리 — OS 로케일을 따른다
- **남은 한계**: (1) 알림 채널 이름·설명은 서비스 `onCreate` 시점(세션 설정 도착 전)에 필요하고 채널은 생성 후 표시명 변경이 제한되므로 여전히 OS 로케일을 따른다. (2) 알림 문구는 `start()` 시점에 고정되므로 세션 도중 언어를 바꾸면 다음 세션부터 반영된다 (`.scratch/i18n/issues/done/02-native-notification-locale.md`)
